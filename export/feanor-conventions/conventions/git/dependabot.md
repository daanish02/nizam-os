# Dependabot

Every project **MUST** have a `.github/dependabot.yml` covering every package ecosystem actually present. Written by `scripts/write-dependabot-config.sh` during `/scaffold` (after scaffolding, not before — it detects single- vs. multi-service by checking whether `services/` exists on disk) — not hand-authored or retyped from this file. `uv` and `bun` are their own distinct Dependabot `package-ecosystem` values (not aliases routed through `pip`/`npm`) — the script uses them directly:

```yaml
version: 2
updates:
  - package-ecosystem: "uv"
    directory: "/backend"
    schedule:
      interval: "weekly"
    groups:
      backend-deps:
        patterns: ["*"]
    open-pull-requests-limit: 5

  - package-ecosystem: "gomod"
    directory: "/backend"
    schedule:
      interval: "weekly"
    groups:
      backend-deps:
        patterns: ["*"]
    open-pull-requests-limit: 5

  - package-ecosystem: "bun"
    directory: "/frontend"
    schedule:
      interval: "weekly"
    groups:
      frontend-deps:
        patterns: ["*"]
    open-pull-requests-limit: 5

  - package-ecosystem: "github-actions"
    directory: "/"
    schedule:
      interval: "weekly"
```

Only include the `package-ecosystem` blocks for stacks the project actually uses — a Go-only backend doesn't need a `uv` block, per the same "generate what's actually needed" rule as everything else in Feanor.

**Multi-service backend** (`services/<role>/`, per `python|go/project-layout.md`): `directory` (singular) does **not** support glob patterns at all — confirmed against GitHub's own docs, not assumed. Use `directories` (plural, a list) instead:

```yaml
- package-ecosystem: "uv"
  directories:
    - "/services/*"
  schedule:
    interval: "weekly"
```

## Rules

- **Weekly**, not daily — daily creates PR noise without meaningfully faster patching for most projects.
- **Grouped** into one PR per ecosystem (`groups: ... patterns: ["*"]`) rather than one PR per dependency — a flood of single-dependency PRs is worse than reviewing one batch.
- `open-pull-requests-limit` capped (5 is a reasonable default) so Dependabot doesn't pile up unreviewed PRs indefinitely.
- Security updates from Dependabot alerts still land immediately regardless of this schedule — the weekly cadence is for routine version bumps, not vulnerability patches.
- A Dependabot PR merges through the normal branch flow (`feature/*` or a dedicated `deps/*` prefix → `qa` → `main`) and the normal test tiers in `branch-test-tiers.md` — it is not exempt from CI just because a bot opened it.
