# SQLite — Dialect-Specific Rules

Load alongside `conventions/cross-stack/database.md`.

> **SQLite is not for production application data.** It is appropriate for: local development, test environments, CLI tools, embedded/offline applications (mobile apps, desktop apps, edge devices), and read-heavy caches that do not require concurrent writes. Any web service with concurrent write traffic, user authentication, or data that cannot afford loss must use a server-based RDBMS.

---

## WAL Mode — Required

Default journal mode (`DELETE`) takes an exclusive lock on the entire database file for every write — completely blocks concurrent readers. Switch to WAL (Write-Ahead Log) mode immediately on every database file:

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;  -- safe with WAL; FULL is unnecessary overhead
PRAGMA busy_timeout = 5000;   -- ms to wait on a locked db before erroring
PRAGMA foreign_keys = ON;     -- disabled by default — always enable
```

WAL allows one writer and multiple concurrent readers. `busy_timeout` prevents "database is locked" errors under light contention. These PRAGMAs must be set on every new connection — they are not persisted permanently (except `journal_mode = WAL`, which is file-persistent once set).

---

## Foreign Keys Are Off by Default

SQLite does not enforce foreign keys unless explicitly enabled per connection:

```sql
PRAGMA foreign_keys = ON;
```

Set this on every connection open. Without it, `INSERT`/`UPDATE` with invalid FK references silently succeed — referential integrity is not enforced.

---

## Type Affinity — Not Types

SQLite uses type affinity, not strict types. A column declared `INTEGER` will accept text values; a `TEXT` column will accept integers. This is a footgun:

```sql
-- SQLite silently accepts this
INSERT INTO orders (amount) VALUES ('not a number');
```

From SQLite 3.37+ use `STRICT` tables to enforce actual type checking:

```sql
CREATE TABLE orders (
  id    INTEGER NOT NULL PRIMARY KEY,
  amount REAL NOT NULL
) STRICT;
```

Always use `STRICT` tables for new schemas in SQLite 3.37+. On older SQLite: add `CHECK` constraints for critical columns.

---

## Concurrency Limits

SQLite supports:
- **Multiple readers, one writer** in WAL mode.
- **No concurrent writers** — writes serialize. Acceptable for dev/test; not for production web services.
- **No user/role system** — all connections have full read/write access. No `app_ro` / `app_rw` separation is possible. This alone disqualifies SQLite from multi-user production use.

---

## UUID Strategy

SQLite has no native UUID type. Store as `TEXT` (36-char hyphen format) or `BLOB` (16 bytes):

```sql
id TEXT NOT NULL PRIMARY KEY  -- UUID v7 as string, generated by application
-- OR
id BLOB NOT NULL PRIMARY KEY  -- UUID v7 as 16 bytes
```

`BLOB` is more efficient; `TEXT` is more readable in SQLite browser tools. For dev/test environments, readability usually wins — use `TEXT`.

---

## Migrations in Test Environments

- Same forward-only, numbered migration files as production — do not use a different migration strategy for dev/test. The test database must be structurally identical to production, or tests do not test the right schema.
- Run migrations against an in-memory SQLite database (`:memory:`) for unit tests that need a fresh schema per test run — fast, isolated, no file cleanup required.
- File-based SQLite for integration tests — gives persistence within a test run, easier to inspect on failure.

---

## When SQLite is Appropriate

| Use case | SQLite OK? |
| :--- | :--- |
| Local development (no shared state) | Yes |
| Automated test suite | Yes |
| CLI tool with local data | Yes |
| Mobile app / desktop app | Yes |
| Edge / IoT device with single writer | Yes |
| Web service with concurrent writes | No |
| Any multi-user service | No |
| Any data requiring user-level access control | No |
| Any production database backing a networked service | No |

## Python

- `aiosqlite` for async access in asyncio services.
- `sqlite3` (stdlib) for synchronous scripts and CLI tools — no install required.
- Set PRAGMAs immediately after `connect()` — use a connection factory or event listener, not inline in each query.

## Go

- `modernc.org/sqlite` — pure Go, no CGo dependency. Preferred for portability.
- `mattn/go-sqlite3` — CGo, faster, requires C toolchain. Use when performance matters.
- Set PRAGMAs via `_pragma` connection string parameters or `PRAGMA` statements immediately after opening the connection.
